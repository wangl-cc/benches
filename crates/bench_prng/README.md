# PRNG Benchmarks

`bench_prng` contains PRNG benchmark cases and two benchmark groups:

- `PRNG u64 Generation`
- `PRNG Bytes Generation`

Each group is a separate Cargo bench target and produces its own `run.json`.
There is no cross-target runner inside this crate.

## Scope

This crate compares throughput of non-cryptographic PRNGs for trusted-data
compute workloads.

It is not:

- a cryptographic security evaluation;
- a statistical certification suite such as TestU01 or PractRand.

## Benchmark Groups

### PRNG u64 Generation

Script entry from the repository root:

```bash
pnpm --dir web bench -- --target prng
```

Direct Cargo target:

```bash
cargo bench -p bench_prng --bench u64_generation -- --profile publish
```

Default output:

```text
target/bench-runs/prng-u64-generation/latest.json
```

This group measures how many `u64` values each generator can produce per
second. It primarily reflects generator core cost.

### PRNG Bytes Generation

Script entry from the repository root:

```bash
pnpm --dir web bench -- --target prng
```

Direct Cargo target:

```bash
cargo bench -p bench_prng --bench bytes_generation -- --profile publish
```

Default output:

```text
target/bench-runs/prng-bytes-generation/latest.json
```

This group measures how quickly each generator fills byte buffers. It reflects
generator cost plus memory write pressure.

## Workload Axis

`u64_generation` uses workload size as element count. `bytes_generation` uses
workload size as bytes. The group prepares the workload shape once per measured
point, and each case creates fresh deterministic RNG state for each sample
window.

PRNG cases seed their RNG in `case.prepare`, not inside each measured
iteration. That keeps setup outside the timed loop while still giving each
sample a deterministic initial state.

Quick profile uses fewer sizes and fewer samples. It is only for smoke tests.

## Case Shape

Cases live in `src/lib.rs`; bench files only assemble groups. A case implements
`harness::BenchmarkCase<W>` for the workload type prepared by its group:

```rust
impl harness::BenchmarkCase<U64Workload> for Xoshiro256PlusPlusCase {
    type State = U64State<rand_xoshiro::Xoshiro256PlusPlus>;
    type Output = u64;

    fn name(&self) -> &'static str {
        "xoshiro256++"
    }

    fn color(&self) -> &'static str {
        "#0f766e"
    }

    fn prepare(&self, workload: U64Workload) -> Self::State {
        U64State::new(workload)
    }

    fn run_once(&self, state: &mut Self::State) -> Self::Output {
        state.next()
    }
}
```

The harness consumes the output with `black_box`; benchmark code does not need
to manually add a black box inside `run_once`.

## PRNGs Included

### PCG family

- **[PCG64](https://docs.rs/rand_pcg/latest/rand_pcg/type.Pcg64.html)**:
  balanced baseline in the PCG family.
- **[PCG64-MCG](https://docs.rs/rand_pcg/latest/rand_pcg/type.Pcg64Mcg.html)**:
  multiplicative variant, often faster state transition.
- **[PCG64DXSM](https://docs.rs/rand_pcg/latest/rand_pcg/type.Pcg64Dxsm.html)**:
  DXSM output variant with a stronger quality margin.

### xoshiro family

- **[xoshiro256++](https://docs.rs/rand_xoshiro/latest/rand_xoshiro/struct.Xoshiro256PlusPlus.html)**:
  fast general-purpose PRNG.
- **[xoshiro256\*\*](https://docs.rs/rand_xoshiro/latest/rand_xoshiro/struct.Xoshiro256StarStar.html)**:
  high-throughput variant with a different output scrambler.

## Reading Results

- `u64_generation` is useful for per-value generator throughput.
- `bytes_generation` is useful when generated bytes are written to memory.
- Small workloads are more sensitive to loop and dispatch overhead.
- Large workloads are more bandwidth-sensitive.

Raw timings are in `measurements[].samples`. The Worker derives throughput,
tail sample-window latency, and stability metrics during ingest.
